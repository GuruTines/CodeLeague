# CodeLeague — фронтенд

React 18 + Vite + React Router. Тёмный интерфейс с анимированными градиентными линиями на главной и бегущей строкой логотипов языков.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

Go-бэкенд должен слушать `http://127.0.0.1:9091` (docker compose из корня проекта). Другой адрес:

```bash
BACKEND_URL=http://127.0.0.1:8080 npm run dev
```

Без бэкенда можно работать на моке:

```bash
npm run mock         # ровно те эндпоинты, что есть в бэкенде сейчас
npm run mock:full    # плюс предлагаемые из BACKEND_TODO.md (GET /me, /me/rooms, /rooms/{id}, /tasks …)
```

Мок повторяет особенности настоящего API (ответы без `Content-Type`, `404 text/plain`, формат ошибок, проверку `Origin` в WebSocket),
так что в режиме `mock` вы увидите ровно то, что получите с текущим бэкендом.

## Страницы

| Адрес | Что там |
|---|---|
| `/` | Приветственная страница: градиентные линии, логотипы языков, как проходит раунд |
| `/tasks`, `/tasks/:id` | Каталог: список слева, условие, лимиты и примеры справа |
| `/rooms/new` | Создание комнаты: название, места (1–15), доступ, выбор задач, предпросмотр |
| `/profile` | Мои комнаты (созданные и где участвую), вход по ссылке-приглашению |
| `/join/:roomId` | Ссылка-приглашение: проверка членства и вступление |
| `/rooms/:roomId` | Комната: участники слева, доска в центре, задачи справа |

Вход и регистрация — окно из шапки. Защищённые страницы без входа показывают приглашение войти.

### Комната

- **Доска** — общий чат по WebSocket. Блоки кода в сообщениях оформляются в рамку.
- **Начать решение** (админ) — выбор задачи и времени (30 с – 120 мин), затем у всех появляется вкладка «Моё решение»:
  таймер, условие, примеры, редактор, выбор языка, «Завершить решение». Черновик хранится в браузере.
- После раунда — вкладка **«Решения»**: код каждого участника, вердикт (если бэкенд его отдаёт), «Перенести на доску» и «Отметить задачу решённой» для админа.
- Справа список задач с отметками. Админ добавляет, убирает, запускает и отмечает решёнными.

Языки решений совпадают с тем, что умеет Judge: Go, Python, Rust, C++ и C.

**Решение — функция (как на LeetCode).** Участник пишет только функцию из сигнатуры задачи: данные приходят
аргументами, ответ уходит через `return`, читать stdin и печатать результат не нужно. Сигнатура приходит вместе с
раундом (`round.task_signature`) и с `GET /tasks/{id}` (`signature`); стартовый код строится из неё в
`src/lib/starter.js` (таблица типов там совпадает с `judge/codeleague-judge/README.md`, раздел «Режим функций»).
Без сигнатуры кнопка отправки заблокирована.

## Как фронтенд живёт без недостающих эндпоинтов

Для каждого отсутствующего эндпоинта есть запасной вариант, а подсказка в интерфейсе ссылается на `BACKEND_TODO.md`:

| Нет на бэкенде | Что делает фронтенд |
|---|---|
| `GET /me` | Верит сохранённому пользователю; при первом `401` просит войти заново |
| `GET /me/rooms` | Показывает комнаты, которые вы создавали или открывали в этом браузере |
| `GET /rooms/{id}` | Участники — те, кого видно по WebSocket; задачи — из памяти браузера; админ — кто создал комнату здесь |
| `GET /tasks`, `/tasks/{id}` | Демонстрационный каталог; в комнату задачи вводятся по id |
| События раундов в WebSocket | Опрос `GET /rounds/active` каждые 3–6 с |

Как только эндпоинт появится, фронтенд начнёт использовать его сам, ничего менять не нужно.

## Продакшен

`npm run build` кладёт сайт в `dist/`. Нужен веб-сервер, который:

1. отдаёт `index.html` для любых путей (SPA);
2. проксирует `/api/` на Go-бэкенд, **отрезая префикс** и сохраняя `Host` (иначе WebSocket не пройдёт проверку `Origin`).

Пример для nginx:

```nginx
location /api/ {
    proxy_pass http://app:9091/;
    proxy_set_header Host $host;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
location / {
    root /usr/share/nginx/html;
    try_files $uri /index.html;
}
```

Адрес API можно поменять переменной `VITE_API_BASE` при сборке (по умолчанию `/api`).

## Если что-то не работает

- **После входа сразу «Сессия закончилась»** — браузер не сохранил cookie: бэкенд ставит её с `Secure`. Chrome и Firefox принимают такую cookie на
  `localhost`/`127.0.0.1`, Safari — нет. Открывайте сайт в Chrome/Firefox или по HTTPS.
- **Чат не подключается (статус «Нет связи»)** — проверьте, что запрос идёт через прокси без подмены `Host` (см. выше).
- **«Нет связи с сервером»** — бэкенд не запущен или `BACKEND_URL` указывает не туда.
- **Отправка решения падает** — проверьте, что у задачи заполнена `tasks.signature`, а тесты записаны в JSON (см. `internal/sql/migration_function_signature.sql`).
