# codeleague-judge

Изолированный микросервис компиляции и проверки решений для CodeLeague (Rust, tokio + axum).
Go-бэкенд отправляет код решения, сигнатуру функции, тесты и лимиты — сервис возвращает вердикт, время и память.
Решение — это **функция** (как на LeetCode): аргументы приходят параметрами, результат отдаётся через `return`.
Ввод-вывод через stdin/stdout пользователю не нужен.

```
src/
  api/      axum-роутер, авторизация по токену, перехват паник
  runner/   конвейер: workspace → harness → компиляция → прогон тестов; описания языков
  function/ типы и сигнатуры, кодирование аргументов/результата, генерация harness (templates/runtime.*)
  sandbox/  запуск процесса с лимитами, замер CPU/памяти, watchdog'и
  judge/    классификация вердикта и сравнение возвращённого значения с ожидаемым
  config.rs, error.rs, models.rs
tests/judge.rs   сквозные тесты (реальные компиляторы + HTTP-роутер)
```

## Запуск

```bash
cargo run --release           # слушает CL_BIND (по умолчанию 0.0.0.0:8081)
cargo test                    # тесты для отсутствующих компиляторов пропускаются
```

Переменные окружения: `CL_BIND`, `CL_API_TOKEN` (Bearer-токен для `/v1/*`), `CL_WORK_ROOT`, `CL_MAX_JOBS`,
`CL_RUN_UID_BASE` (<=0 отключает смену uid), `CL_REQUIRE_NAMESPACES`, `CL_MAX_TESTS`, `CL_MAX_TIME_LIMIT_MS`,
`CL_MAX_MEMORY_LIMIT_MB`, `CL_MAX_OUTPUT_BYTES`, `CL_COMPILE_TIMEOUT_SECS`, `CL_CC/CXX/PYTHON/RUSTC/GO`, `RUST_LOG`.

## API

`GET /healthz` · `GET /v1/languages` · `POST /v1/judge`

```jsonc
// POST /v1/judge
{
  "language": "c",                // c | cpp | python | rust | go  (алиасы: c++, py, python3, rs, golang)
  "source_code": "int solve(int a, int b) { return a + b; }",
  "signature": {                  // обязательно
    "name": "solve",
    "params": [{ "name": "a", "type": "int" }, { "name": "b", "type": "int" }],
    "return_type": "int"
  },
  "tests": [{ "input": "[2, 3]", "expected_output": "5" }],   // JSON: массив аргументов / возвращаемое значение
  "time_limit_ms": 1000,          // CPU-время на тест
  "memory_limit_mb": 64,          // пиковый RSS на тест
  "stop_on_first_failure": true   // по умолч. true
}
```

## Режим функций

Типы: `int` (32 бита), `long` (64), `double`, `bool`, `string`; каждый можно обернуть в `[]` или `[][]`
(`int[]`, `string[][]`). Запрос с неизвестным типом, невалидным именем (только `[A-Za-z_][A-Za-z0-9_]*`),
числом аргументов в тесте не по сигнатуре или `expected_output`, не подходящим к `return_type`, получает 400 с
номером теста. Числа сравниваются точно, а если хотя бы одна сторона — дробное, то с допуском `1e-6`.

Судья дописывает к коду пользователя сгенерированную точку входа (**harness**): она читает аргументы со stdin,
вызывает функцию и печатает результат после маркера `@@CL_RESULT@@`. Всё, что решение печатает само (отладка),
попадает в `tests[].stdout` и на вердикт не влияет. Вердикт `ACCEPTED` требует, чтобы функция действительно
вернула значение: `exit()` внутри решения, исключение или неверный тип результата дают `RUNTIME_ERROR`.
Harness дописывается **после** кода пользователя, поэтому номера строк в ошибках компиляции совпадают с редактором
(в Go harness лежит в отдельном `harness.go`). Решение не должно определять `main`.

Как тип сигнатуры выглядит в коде пользователя (имя функции — `signature.name`, параметры по порядку):

| тип | Python | Go | C++ | Rust | C |
|---|---|---|---|---|---|
| `int` | `int` | `int` | `int` | `i32` | `int` |
| `long` | `int` | `int64` | `long long` | `i64` | `long long` |
| `double` | `float` | `float64` | `double` | `f64` | `double` |
| `bool` | `bool` | `bool` | `bool` | `bool` | `bool` (`<stdbool.h>`) |
| `string` | `str` | `string` | `std::string` | `String` | `char *` (NUL-терминированная) |
| `T[]` | `list` | `[]T` | `std::vector<T>` | `Vec<T>` | `T *` + длина |
| `T[][]` | `list[list]` | `[][]T` | `std::vector<std::vector<T>>` | `Vec<Vec<T>>` | `T **` + число строк + длины строк |

* C++ — параметры можно объявлять как значение, `&` или `const &`. Rust — параметры принимаются **по значению**.
* C: после каждого параметра-массива идёт `int` с длиной (`T[][]`: `int rows, int *cols`). Массив в результате
  возвращается указателем на `malloc`-память, а длина — через **завершающие** out-параметры: `int *return_size`
  (для `T[][]` ещё и `int **return_cols`). Пример: `int *solve(int *nums, int nums_size, int target, int *return_size)`.
* Python: результат должен быть точного типа (`int` для `int`/`long`, `bool` для `bool`, `str` для `string`);
  `5.0` вместо `5` — `RUNTIME_ERROR`.
* Не подходят: `#define int long long` в C/C++ (ломает harness), функции с другим числом параметров, чем в сигнатуре
  (ошибка компиляции).

Служебный формат (stdin harness): токены через пробел; `string` — hex от UTF-8 (`-` для пустой), `bool` — `1`/`0`,
массив — длина и элементы. Он нужен только harness'ам и судье.

Ответ: `verdict` (`ACCEPTED`, `WRONG_ANSWER`, `TIME_LIMIT_EXCEEDED`, `MEMORY_LIMIT_EXCEEDED`, `RUNTIME_ERROR`,
`COMPILATION_ERROR`), `passed`, `total`, `time_ms`, `memory_kb` (максимумы), `compile_output` (при CE) и
`tests[]` с вердиктом, временем, памятью, `exit_code`/`signal`, усечёнными `stdout`/`stderr`.
Ошибки сервиса: `{"error":{"code","message"}}` (400 — невалидный запрос, 401 — токен, 422 — язык недоступен, 500 — сбой).

Приоритет вердикта: превышение времени/памяти → крэш/ненулевой код → проверка возвращённого значения.
Переполнение вывода (`CL_MAX_OUTPUT_BYTES`) даёт `RUNTIME_ERROR` с пояснением в `message`.

## Модель изоляции

Для каждого запуска (и компиляции тоже):
* отдельная сессия и группа процессов — при завершении/лимите убивается вся группа (в т.ч. потомки);
* `RLIMIT_CPU/AS/FSIZE/NOFILE/NPROC/STACK/CORE`, `PR_SET_NO_NEW_PRIVS`;
* новые network/IPC/UTS namespaces (нужен `CAP_SYS_ADMIN`; при отсутствии — предупреждение в логе,
  либо отказ при `CL_REQUIRE_NAMESPACES=true`);
* при запуске от root — смена на непривилегированный uid/gid. У каждого слота параллельности свой uid
  (`CL_RUN_UID_BASE + слот`), так что одновременные решения не видят файлы друг друга;
* watchdog по стеночному времени (`2×TL + 0.5с`) и по памяти (опрос `VmHWM` из `/proc` каждые 2 мс);
* отдельный пустой рабочий каталог на каждый тест, удаляется после.

Измерения: время — user+sys из `wait4` rusage; память — пик `VmHWM`.

### Ограничения
* **Нет seccomp и chroot/mount namespace**: код пользователя видит файловую систему контейнера
  (только чтение, из-за смены uid). Запускайте сервис в контейнере/VM без секретов, rootfs read-only
  (кроме `CL_WORK_ROOT`). Для жёсткой изоляции добавьте seccomp-профиль или gVisor/Firecracker.
* **Память**: лимит проверяется опросом раз в 2 мс; программа, выделившая память и завершившаяся быстрее,
  может проскочить. `RLIMIT_AS` (2×лимит+256 МБ; для Go отключён) — страховка. cgroup v2
  (`memory.max`/`memory.peak`) — естественное расширение `sandbox/`.
* Для процессов, завершившихся до первого опроса, память берётся из `ru_maxrss` (может включать память родителя).
* Компиляторы должны быть установлены глобально и доступны непривилегированному uid
  (не в `~/.cargo`/`~/.rustup`; rustup-прокси не подойдёт). См. `Dockerfile`.
* Кэш сборки Go общий между запусками одного слота (ускоряет компиляцию).
* Параллельные задачи делят CPU и могут искажать замеры; `CL_MAX_JOBS` по умолчанию = числу ядер.
* Harness читает аргументы и печатает результат внутри того же процесса, что и решение, а время и память
  включают этот разбор. Решение, знающее маркер, может напечатать свой «результат», но ожидаемых ответов
  оно не получает, так что подделать верный ответ на скрытом тесте нельзя.
* Не поддерживаются `void`/изменение аргумента «на месте», деревья, списки и другие структуры LeetCode.
* gRPC не реализован — только REST. Новый язык добавляется в `runner/language.rs`.
