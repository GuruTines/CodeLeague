# План разработки проекта

## 1. АВТОРИЗАЦИЯ

- [x] **1.1. Система авторизации пользователей.**

  Пользователь выполняет регистрацию/вход и получает сессию, которая хранится в Redis и cookie определённое время (7 дней).

  Пользователь может выполнить logout и выйти из аккаунта до истечения TTL.

## 2. СОЗДАНИЕ КОМНАТЫ

- [x] **2.1. Создание комнат.**

  Пользователь создаёт комнату. Сама комната — отдельная область, включающая свои задачи и определённое число пользователей.

  Структура комнаты:

  - `id`
  - `title`
  - `is_private`
  - `capacity`

- [x] **2.2. Выбор задач для комнаты.**

  После создания комнаты пользователь может выбрать задачи из общего каталога, которые будут добавлены в комнату для решения.

  Устанавливается связь M:N между комнатой и задачей через таблицу `rooms_tasks`.

  | room_id | task_id | success |
  |---|---|---|
  | uuid1 | taskID1 | false |
  | uuid1 | taskID2 | true |

  `success` — метка, показывающая, решена или не решена задача в текущей комнате.

- [x] **2.3. Создание ссылки-приглашения.**

  Сервис формирует ссылку-приглашение для комнаты. По этой ссылке могут присоединяться пользователи.

## 3. УЧАСТНИКИ В КОМНАТЕ

- [ ] **3.1. Присоединение к комнате.**

  Пользователи могут вступать в комнаты. Если комната отмечена как приватная, то присоединиться можно только по ссылке. Если комната общая, то присоединиться можно по ссылке или через список комнат.

- [ ] **3.2. Проверка вместимости комнаты.**

  При вступлении сервис должен проверить число участников комнаты. Если комната заполнена, сервис выдаёт ошибку. Если места есть, создаётся запись в связующей таблице `users_rooms`.

  | user_id | room_id | is_admin | is_muted |
  |---|---|---|---|
  | 1 | uuid1 | true | false |
  | 2 | uuid1 | false | false |
  | 3 | uuid1 | false | true |

  Таблица помогает определить число и самих участников комнаты, их роль и ограничения.

- [ ] **3.3. Ограничения и права участников.**

  Важные ограничения:

  - Администратор в комнате может быть только один.
  - Только администратор может выполнять следующие действия:
    - мутить пользователей;
    - добавлять задачи;
    - удалять задачи.

## 4. ДЕЙСТВИЯ В КОМНАТЕ

- [ ] **4.1. Общая доска комнаты.**

  На данном этапе сервис имеет несколько пользователей, комнату с задачами и участниками.

  Каждый участник комнаты видит общую доску, некоторую информацию о комнате и список задач, которые отмечены как решённые или нерешённые в рамках текущей комнаты.

- [ ] **4.2. Начало решения задачи.**

  Администратор использует кнопку «Начать решение». При нажатии ему предоставляется возможность:

  - выбрать интервал времени, в течение которого участники будут решать задачу, чтобы никто не сидел бесконечно;
  - выбрать задачу, которая будет решаться.

## 5. РЕШЕНИЕ ЗАДАЧ ВСЕМИ УЧАСТНИКАМИ

- [ ] **5.1. Индивидуальная область решения.**

  Каждый участник, в том числе администратор, получает отдельную область, в которой видит:

  - время, оставшееся на решение;
  - условие задачи;
  - примеры входных и выходных данных;
  - область для написания кода.

- [ ] **5.2. Завершение решения.**

  Независимо от того, верное решение или нет, пользователь может нажать кнопку «Завершить решение» и перейти в режим ожидания остальных участников, если ещё кто-то решает задачу.


## 6. ПРОСМОТР РЕШЕНИЙ

- [ ] **6.1. Просмотр решений участников.**

  После того как все закончили решение, участники могут посмотреть решения друг друга.

- [ ] **6.2. Перенос решения на общую доску.**

  Администратор может выбрать пользователя и нажать кнопку «Перенести решение». Это скопирует текст решения задачи на общую доску.

  На общей доске участники могут обсудить решение задачи.

- [x] **6.3. Отметка задачи как решённой.**

  После обсуждения администратор помечает задачу как решённую. В таблице `rooms_tasks` поле `success` становится `true` для текущей комнаты.

  Задача считается выполненной в рамках текущей комнаты. Тогда в таблице rooms_tasks поле is_success становится равной true для решенной задачи. Решение об этом принимает только админ. Например помечая задачу галочкой.
